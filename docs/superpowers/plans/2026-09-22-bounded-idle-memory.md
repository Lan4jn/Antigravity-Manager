# 空闲内存保留治理计划

目标：约束 Responses 历史、全局缓存和日志任务的实际保留数据；空闲时释放过期数据，保持响应完整及用量统计。按用户已批准的三项目标实施，不改历史无关测试。

方案：沿用标准容器和 Tokio；预算淘汰整条记录，不截断签名、工具定义或历史。历史缺失明确返回错误。预算是缓存数据估算/字符串容量，不是进程 RSS 保证。沿用现有 TTL，每分钟清理。

- [x] Responses 历史：先补过期读取、祖先释放、容量和历史完整性测试；限制全局存活节点数据 64 MiB、单链 16 MiB、索引 1000 条；共享祖先只计一次；超预算整条淘汰/拒绝，缺失 previous_response_id 返回明确 400。主动清理可随生命周期取消。
- [x] 全局缓存：先补字节超限和过期清理测试；签名所有层合计预算 32 MiB，SI/tools 各 8 MiB；淘汰整个 LRU 条目；拒绝超大单条；保留 TTL 和有效命中语义。
- [x] 日志：减少完整正文 clone，写入任务有界并等待完成；关闭正文日志时跳过采集正文但保留 usage 提取；测试转发和用量兼容性。
- [x] 检查 cargo check、针对测试及完整 proxy 测试；与既有 8 项失败比较；复核规格和代码质量。记录实际结果和风险。

验证采用隔离 ABV_DATA_DIR。测试应先红后绿；容量计算不得深拷贝正文。生产 RSS 仍需要部署后验证。

## 实现决定与验收边界

- 在用户批准的现有工作区创建 `codex/bounded-idle-memory` 分支。
- 签名四层负载容量预算分别为工具 2 MiB、模型族 2 MiB、会话签名 24 MiB、reasoning 4 MiB，合计 32 MiB；包含字符串 key 的容量，不含容器元数据。
- Responses 预算统计共享节点唯一估算堆容量，包含仍被在途 SessionParent 持有的节点；另限制链深度 1000，防止无限物化及递归析构。
- 日志在请求体读取前最多准入 4 条完整采集流水线，直到数据库任务结束；超出时等待，增加排队延迟而不截断响应。完整日志 move 到写入任务；取消等待方不会提前释放写入任务持有的 permit。
- 关闭日志后仍解析 usage；单个 SSE 事件超过 64 KiB 时短暂落盘，使用 serde 忽略输出字段，仅提取用量。单事件沿用 100 MiB 监控上限，超限/磁盘失败会告警并可能缺少该事件用量，客户端转发继续。
- 额外修复同属日志常驻内存问题的 error 字段：内存和 UI 事件使用 16 KiB UTF-8 安全预览，数据库保留完整错误。
- 保留原 TTL：Responses 1 小时，签名 2 小时，SI/tools 30 分钟；每分钟扫描释放已过期数据。并非停止请求一分钟后清空全部缓存。
- 不承诺 RSS 回到启动值；HTTP 在途输入、物化副本、分配器保留页与磁盘页缓存不属于上述缓存预算。
